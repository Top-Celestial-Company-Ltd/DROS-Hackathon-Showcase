# DROS-VEP #05 解法對應說明書 (Solution Mapping)
# Track 05｜擴充賽道 · 普惠金融：移工數位信任與防詐憑證機制

> **VEP 識別名稱**：DROS MigraTrust VEP #05  
> **適用法規**：金融監督管理委員會（金管會）指引、反洗錢法（AML）、勞動部外籍勞工管理規定、行政院移工數位金融政策  
> **核心痛點**：逾 87 萬移工面臨開戶障礙，同時容易遭冒名利用；如何建立一套「能被信任、又不被冒用」的數位身分與憑證機制？  
> **專利保護**：U.S. PPA No. 64/111,973 (Patent Pending)

## 🎯 痛點精確解讀 (Problem Framing)

| 痛點維度 | 問題描述 | 傳統方案的缺口 |
| :--- | :--- | :--- |
| **開戶障礙** | 移工無台灣本國身份，現行銀行 KYC 要求往往排除外籍人士 | 無法依信任層級漸進開放，不是全開就是全關 |
| **文件多元碎片化** | 移工持有多國護照 + 台灣 ARC 居留證 + 勞動部許可，三件各自驗證，無法合一 | 任一文件偽造即可繞過，無複合綁定機制 |
| **冒名詐騙高風險** | 詐騙集團盜取移工文件開立人頭帳戶，洗錢轉帳 | 事後追查困難，缺乏帶內即時攔截 |
| **SIM Swap 攻擊** | 攻擊者換裝移工 SIM 卡截取 OTP，發起大額匯款 | OTP 本身不驗行為異常，無硬性熔斷 |
| **撤銷困難** | 移工發現帳戶被盜用後，無法即時凍結，需聯絡銀行等待人工處理 | 凍結延遲數分鐘至數小時，詐騙已完成 |

## 🏗️ DROS MigraTrust VEP 解法架構

### 三層信任矩陣 (Three-Tier Trust Matrix)

```
┌──────────────────────────────────────────────────────────────────────┐
│              DROS MigraTrust VEP — Trust Tier Permission Matrix      │
├─────────────────┬──────────────────────┬──────────────────────────────┤
│ 信任層 (Tier)   │ 文件要求              │ 金融操作權限                  │
├─────────────────┼──────────────────────┼──────────────────────────────┤
│ L1 基礎信任     │ ARC 居留證 + 護照     │ 開戶、查餘額、匯款≤NTD 3,000  │
│ L2 強化信任     │ + 勞動部勞動許可      │ 大額匯款 (HITL 確認)、貸款詢問 │
│ L3 高風險禁區   │ 任何等級              │ 跨行轉帳、海外第三方、大額提領  │
└─────────────────┴──────────────────────┴──────────────────────────────┘
         ↑ PERMIT 自動放行        ↑ HITL 強制確認      ↑ DENY 硬性禁止
```

### 技術棧整合層 (Integration Stack)

| 層級 | 技術組件 | 角色 |
| :--- | :--- | :--- |
| **L0 - 多文件複合綁定** | ARC-NIA API + 護照 OCR + MOL 勞動許可 API | 三件文件合一 DIT 密碼學 Token |
| **L1 - 帶內代理層** | DROS VEP C-ABI Gate | 26.1μs 帶內攔截所有金融 Tool Call |
| **L2 - 行為異常偵測** | VEP Anomaly Policy Engine | SIM Swap 特徵 / 冒名異常分數即時評估 |
| **L3 - HITL 確認層** | 移工 App 推播 + 300s 逾時 | 大額匯款強制本人 App 確認，不依賴 OTP |
| **L4 - 稽核層** | SHA-256 Merkle Chain | 每筆金融操作留存不可篡改密碼學憑證 |

## 🔒 6 大信任要點對應說明 (Governance Gap Memo)

### 1. Principal — 代表誰？

**問題**：金融系統如何確認「操作帳戶的是移工本人」？

**DROS 解法**：
- **多文件複合 DIT**：護照號碼 + ARC 居留證號 + 勞動許可號三件合一密碼學綁定
- 任何單一文件偽造均無效，需三件同時匹配才能通過 DIT 驗證

```json
{
  "dit_version": "v1.2-dros-migra",
  "principal": "陳阮明 (Tran Nguyen Minh)",
  "nationality": "VN",
  "arc_id": "AA12345678",
  "passport_no": "B12345678",
  "work_permit": "MOL-WP-2026-08-88821",
  "trust_tier": "L2"
}
```

---

### 2. Authorization — 被授權做什麼？

**問題**：如何在開放普惠金融的同時，防止高風險操作被濫用？

**DROS 解法**：
- **三層漸進式信任矩陣**，普惠開戶不意味著開放所有金融操作
- L1 移工可開戶但匯款上限 NTD 3,000；追加勞動許可後才升 L2 可大額匯款（仍需 HITL）
- 跨行轉帳與海外第三方帳戶永久 DENY，不論信任層級

---

### 3. Tool / Action — 哪些動作被控制？

**問題**：詐騙集團指示移工帳戶接收詐騙款項後轉帳海外，如何阻止？

**DROS 解法**：
- `overseas_3rd_party()`、`cross_bank_transfer()` 一律 **HTTP 403**，26.1μs 決策
- 不依賴移工理解詐騙手法，VEP 帶內物理層硬阻
- 完整行為記錄進 Merkle Audit Chain，可供法院舉證

---

### 4. Policy Gate — 高風險動作如何被擋？

**問題**：SIM Swap 攻擊者截取 OTP 後，傳統系統無法識別，DROS 如何防禦？

**DROS 解法**：
- **行為異常偵測 Policy Gate**：不單純驗 OTP，而是評估行為特徵向量（新 SIM 號碼 + 大額匯款 = 高異常分數）
- 異常分數超過閾值（如 0.90）即自動觸發帳戶凍結
- 凍結期間所有 API 呼叫收 403，等待人工審查解凍

---

### 5. Audit Log — 如何追溯稽核？

**問題**：移工被詐騙後申訴，如何提供可被法院採信的證據？

**DROS 解法**：
- **SHA-256 Merkle Hash Chain**：每筆開戶、匯款、攔截、凍結均產生密碼學雜湊
- 每筆 Log 含：時間戳、移工 DIT 身份、金融操作類型、決策結果、異常評分
- Merkle 前後鏈結，篡改數學上可被驗證
- 評審可在展示台直接點擊每筆 Log 彈出完整憑證

---

### 6. Expiry / Revocation — 如何即時凍結？

**問題**：移工發現帳戶被冒用，傳統方式需打電話等人工凍結，詐騙已完成怎麼辦？

**DROS 解法**：
- **O(1) RCU 原子換指針**：移工或雇主從 App 點擊「緊急凍結」
  - 記憶體中 Token 狀態原子切換（< 1μs）
  - 下一筆 API 請求立即收到 `HTTP 403 ACCOUNT_FROZEN`
  - 無需等待人工介入，無延遲視窗

## 🆚 為什麼這題不難？DROS 的核心優勢

傳統普惠金融方案面臨「開放 vs 安全」的零和困境：

- **開放** → 詐騙風險高
- **嚴格** → 移工無法開戶

**DROS MigraTrust VEP 打破零和**：
- 精確的**漸進式信任層**讓合規移工能開戶（解決普惠）
- VEP 帶內的**硬性行為邊界**讓詐騙動作不可能執行（解決安全）
- 兩者不衝突，因為「能開戶」和「能轉帳給詐騙集團」是完全不同的授權層
